# Backoffice 1.9.107 — product synchronization

Base: main d90607f (PR #167, 1.9.106).

The installed entrypoint is index.html. Its inline engine owns localStorage and Supabase synchronization; cloud.js/db.js are not imported by this entrypoint.

## Cause and implementation

The independent product sender compared complete objects to the editing base. Independent remote field changes therefore produced unresolved conflicts. The relational bulk sender could subsequently retry the same products and raise a global conflict. Review confirmation used another remote-first writer, refusing offline or busy sessions.

Product writes now use the existing persistent product queue. Three-way recursive field comparison combines independent object fields; arrays remain atomic. Divergent identities, duplicate codes, deleted remote rows and missing bases remain conservative. Real conflicting fields are displayed with base/local/Cloud values. Before reconciliation, append-only recovery records preserve all versions; these can be exported from Cloud Sync. Resolution stages a local product and re-reads Cloud before compare-and-swap; it does not force an entire remote snapshot over another version.

Acknowledgements clear only the sent version. Edits made during a request remain queued with the acknowledged base. Compare-and-swap uses the exact remote updated_at, and the next timestamp strictly advances it even when the remote clock is ahead. Queries and writes are user-scoped. No database schema, authorization, business rows, or credentials were changed during implementation.

New product-only dirty cycles skip operational synchronization. Other dirty writes invalidate that optimization. Legacy operational conflicts are retained rather than silently discarded. A product conflict does not prevent other queued products from sending. Transient write errors have bounded retries; field conflicts do not cause retry loops. Reviews now save locally through save('products') without waiting for another review to reach Cloud.

Reconnect/focus reception preserves pending products and protects against reads overtaken by local edits. Realtime notifications trigger an authoritative row read rather than applying events in arrival order. Product deletions are conservatively not applied by the new realtime receiver (no tombstone reconciliation added in this release).

PWA version and service-worker cache are advanced together. In-place update refuses navigation during product writes. Existing storage and queues are retained.

## Recovery

Reconciliation copies use ae_product_recovery_19107_* keys, separate from the existing queue. Export is read-only. A code rollback can revert this commit without clearing storage; restore exported fields through the product editor rather than replacing the entire device database. No automated global restore is performed.
