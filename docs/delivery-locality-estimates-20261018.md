# Owner-only locality planning estimates

Adds planning references to the existing Backoffice delivery settings. A reference is NOT a checkout quote, does not cover every address, and is not a min/max interval. User-triggered calculations use the numeric costs currently shown, including unsaved edits and expected deliveries per departure. Changing costs invalidates displayed results and in-flight stale responses. Other locality names can be added to the temporary simulation without creating or enabling zones.

API /api/delivery-estimates runs in the existing Loja backend with explicit environment enablement. It validates the caller's session through the existing Supabase artessencia_is_owner_v1 RPC; no service_role key, new SQL function or table. Requests from other browser origins are rejected. CORS permits the production Backoffice origin and one explicitly configured Preview origin. There are bounded request/concurrency guards and a server-only 12-hour route cache. Prices are recomputed on every request; origin changes invalidate route cache keys.

The server ignores client-supplied coordinates, fee and activation flags. It uses the private configured atelier origin and actual separate outbound/return road segments. Numeric cost validation and exact rounding reuse the same pricing function as checkout, without producing signed tokens. Castelejo uses its current fixed base. Settings can remain disabled while the owner simulates; the API never writes settings, zones, customers or orders.

Reference geocoding is explicitly regional and distinct from house validation. It requires an exact unique locality name, Portugal, Castelo Branco region and municipality metadata. When the provider only identifies a parish, reviewed public municipal provenance is required; currently Alcaide is documented by https://cm-fundao.pt/index.php/12-juntas-de-freguesia/39-alcaide (reviewed 2026-10-18). This small provenance record is not a delivery-area or postal mapping. Ambiguous or missing references remain unavailable, not zero-priced. No locality coordinate is accepted by the checkout house validator.

Validation: 78 automated tests, plus isolated Backoffice locality simulation, numeric pricing and checkout browser scenarios at 412 and 1280. The UI tests verify no automatic requests, authenticated calculation, current unsaved costs, changed-cost and in-flight invalidation, missing session refusal, safe locality text and no mobile overflow. Live authenticated owner use remains an operator acceptance check; no owner session credentials were extracted for tests.

Frontends remain draft protected Previews. Backoffice version 1.9.12-preview, APP_VERSION/SW cache/version.json aligned. No production tariff or delivery activation changed; shop remains closed. Reference examples are estimates only, not customer prices applied in production.

Live reference verification: the Alcaide locality point was resolved using regional search, exact name and municipal parish provenance. Separate road legs: 14595 + 14636 metres; 1281 + 1311 seconds. At the simulation's agreed numeric costs and 3 expected deliveries, the shared reference estimate is EUR 3.92. This is not a price for every address in Alcaide.

The Backoffice calls a same-origin server proxy, never the protected Loja Preview directly from the browser. In Preview, the proxy uses the Backoffice server's short-lived Vercel OIDC token to the fixed Loja Preview branch endpoint. It never forwards that token to the browser or any arbitrary target and never follows redirects. Existing Supabase owner authorization remains mandatory for estimates. Production forwarding omits the Vercel token. A Preview-only read-only GET health check tests only upstream method refusal, without owner sessions or map/provider calls. If cross-project Trusted Sources does not already allow Backoffice Preview -> Loja Preview, operator authorization is required before adding that narrowly scoped rule. Deployment Protection remains enabled.

Proxy unit test passed and locality UI tests passed after moving requests to the same origin. Full live owner-session acceptance remains pending.
